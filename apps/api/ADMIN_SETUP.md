# راه‌اندازی امن مدیر اصلی آوگون

این عملیات فقط از محیط سرور و با دسترسی مستقیم به محیط اجرای API انجام می‌شود. هیچ endpoint عمومی برای تبدیل کاربر به مدیر وجود ندارد.

## پیش‌نیازها
1. API و دیتابیس PostgreSQL را راه‌اندازی و migrationهای پروژه را اجرا کنید.
2. در محیط production مقدار تصادفی و محرمانه‌ای برای `JWT_SECRET` با حداقل ۳۲ کاراکتر تنظیم کنید.
3. حساب موردنظر باید قبلاً از مسیر عادی ثبت‌نام کرده و شماره موبایل یا ایمیل آن را تأیید کرده باشد.
4. مطمئن شوید هنوز هیچ کاربری نقش `ADMIN` ندارد.

## ساخت اولین مدیر
در پوشه `apps/api`، فقط یکی از دو شناسه را تنظیم کنید:

```bash
export ADMIN_BOOTSTRAP_EMAIL='admin@example.com'
# یا به‌جای ایمیل:
# export ADMIN_BOOTSTRAP_PHONE='+491234567890'

export ADMIN_BOOTSTRAP_CONFIRM='CREATE_FIRST_ADMIN'
npm run build
npm run admin:bootstrap
unset ADMIN_BOOTSTRAP_EMAIL ADMIN_BOOTSTRAP_PHONE ADMIN_BOOTSTRAP_CONFIRM
```

فرمان فقط زمانی نقش را تغییر می‌دهد که:
- عبارت تأیید دقیق تنظیم شده باشد؛
- دقیقاً یک ایمیل یا شماره تلفن تعیین شده باشد؛
- حساب از قبل وجود داشته باشد؛
- هیچ مدیر دیگری در دیتابیس وجود نداشته باشد.

عملیات در تراکنش Serializable انجام می‌شود تا دو اجرای هم‌زمان نتوانند دو مدیر اولیه بسازند. اجرای دوباره پس از ایجاد مدیر، بدون تغییر داده رد می‌شود.

## ورود به پنل
پس از اجرای موفق، از حساب خارج شوید و دوباره با همان ایمیل/شماره و OTP وارد شوید تا نشست جدید صادر شود. نقش فعلی از دیتابیس در هر درخواست API بررسی می‌شود؛ بنابراین تغییر یا لغو نقش در دیتابیس پس از صدور توکن نیز در درخواست بعدی اعمال می‌شود.

پنل:
`/admin.html`

API پیش‌فرض:
`http://localhost:4000`

برای انتشار واقعی، `WEB_ORIGIN` را روی origin دقیق سایت و `AVGOON_API_URL` را روی آدرس HTTPS API تنظیم کنید. سرویس ارسال OTP نیز باید پیش از استفاده واقعی پیکربندی شود.

## نکته امنیتی
- این فرمان را از ترمینال سرور اجرا کنید؛ مقادیر محرمانه را در Git، فایل‌های عمومی یا پیام‌های پشتیبانی قرار ندهید.
- دیتابیس production را بدون backup و برنامه بازگشت تغییر ندهید.
- برای مدیران بعدی، حساب را با فرایند مدیریت دسترسی امن ایجاد کنید؛ فرمان bootstrap فقط برای اولین مدیر است.
